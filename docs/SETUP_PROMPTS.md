## Prompt 1: ElevenLabs (already built, needs keys and a real test)

```
I have a project called Ofrenda in this folder: an offline Día de los Muertos memory altar.
Python stdlib backend (server.py) + one index.html, local Gemma via Ollama.
It already has OPTIONAL ElevenLabs voice, off unless ELEVENLABS_API_KEY is set:
  - "Record a story" -> POST /api/transcribe -> ElevenLabs speech-to-text (model_id scribe_v2)
  - "Listen" -> POST /api/speak -> ElevenLabs text-to-speech (needs ELEVENLABS_VOICE_ID)
The code was written from the docs but NEVER run against the real ElevenLabs API.

Your job: make it work for real, and tell me the truth about what happened.

1. Read server.py (functions multipart, elevenlabs, transcribe, speak) and the record/listen code in index.html.
2. Ask me for my ElevenLabs API key and a generic narrator voice ID. Never write the key into any file
   or commit it. Pass it only as environment variables.
3. Start Ollama and `python3 server.py` with the variables set. Open http://localhost:8000.
4. Test Record a story with a short real recording. Browsers record WebM/Opus. If ElevenLabs rejects it,
   read the exact error body, then fix it (for example a different filename/MIME, or convert to WAV in the
   browser). Do not guess: fix what the error says, then re-test.
5. Test Listen on a remembrance and on an echo reply. Confirm audio actually plays.
6. Confirm that with no key set the buttons are hidden and the app still works fully offline.
7. Do NOT add voice cloning. Use a generic narrator voice only. That is a deliberate choice in this project.
8. Keep the privacy wording honest: voice is the one feature that sends audio/text to ElevenLabs.

Finish by telling me: what worked, what you had to change, and anything you could not verify.
Update README.md only if behaviour changed. Do not touch WRITEUP.md placeholders.
```

## Prompt 2: Backboard (NOT built yet, real integration)

```
I have a project called Ofrenda in this folder: an offline Día de los Muertos memory altar.
Python stdlib backend (server.py, no pip dependencies), one index.html, local Gemma via Ollama,
plus an optional Node "echo-agent" (Mastra) service. Read README.md and server.py first.

I want to enter the "Best Use of Backboard" prize in the Hacktoberfest Open-Source AI Challenge.
Prize text: "Build with R-CLI, Backboard's open-source terminal coding agent, compare open-weight models
through a single Backboard API key, or give an open-source project's assistant memory and RAG."
Backboard's pricing page says the free tier has $5 credit and no credit card.

Backboard is NOT integrated yet. I have not seen its API docs, so do not invent endpoints.

Your job:

1. Read the real docs first: https://docs.backboard.io (start with the dashboard/getting-started page, then

   Write down, with the source page, the exact base URL, auth header, and request/response shapes you will use.
   If a page does not say, say so. Do not fill gaps from memory.
2. Ask me for my Backboard API key (from app.backboard.io). Never write it to a file. Environment variable

3. Pick the SMALLEST integration that is genuine and honest, in this order of preference:
   a) Open-weight model comparison: extend the existing "Compare" feature (POST /api/compare in server.py
      and compare() in index.html) so the same remembrance can be generated by an open-weight model
      reached through Backboard's single API key, shown next to local Gemma with seconds and cost.
      Use only models the docs show as open-weight. Say which model and why.

   Do only what you can verify with my real key. If something does not work, report it and stop rather
   than faking it.
4. Hard constraints:
   - The default experience must stay fully offline. Backboard is opt-in, off unless BACKBOARD_API_KEY is set.
   - Any feature that sends stories to Backboard must be labelled orange/cloud in the "What runs where"

   - Python standard library only in server.py (use urllib like the existing code).
   - No secrets in files. ofrenda_data/ stays gitignored.
5. Test with the real key: show me the actual response, the measured time, and the real cost reported by
   Backboard if it reports one. Also test the failure paths: no key, wrong key, network down.
6. Update README.md with the setup steps. In WRITEUP.md, replace nothing I wrote, but add a short honest
   section for Backboard and a matching bullet under "Prize Categories", using only things that actually ran.
   Leave my [PASTE ...] placeholders alone.
7. Finish by telling me: what you built, what you verified with the real key, what you could not verify.
   If you could not make a genuine integration work, say so plainly and tell me to remove the Backboard
   bullet from my post.
```
